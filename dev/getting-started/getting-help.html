Getting Help ​

Something not working? Work through these in order: most problems are a config typo or a setup issue, and both are quick to rule out.

1. Check your config ​

Paste your card YAML (or the whole dashboard) into Check Your Config. It finds options that don't exist, misspelt preset, animation and colour names, and values of the wrong kind, each with the line and a suggestion. Fix what it reports first: a config LCARdS doesn't understand is silently ignored, which often looks like a bug.

Using Claude with the LCARdS skill? Paste the YAML and ask it to check and fix it.

2. Run the health check ​

Open the LCARdS sidebar panel → Welcome tab → Support & system info.

The checklist covers the most common causes of problems:

CheckWhat it means
Home Assistant versionLCARdS requires Home Assistant 2026.10 or newer.
Frontend = integration versionIf these differ, your browser is running a cached copy of an older LCARdS. Hard-refresh (Ctrl+Shift+R / Cmd+Shift+R), or clear the companion app's frontend cache. If you just updated, restart Home Assistant.
UI eXtension (UIX) / card-modHA-LCARS styles Home Assistant through UIX. card-mod no longer works with current Home Assistant and conflicts with UIX. Uninstall it in HACS and remove its extra_module_url line from configuration.yaml.
card-mod in extra_module_urlA leftover frontend: extra_module_url entry still loads card-mod. Remove it and restart.
custom:layout-cardShown when custom:layout-card is installed. LCARdS cards can shrink inside it; switch to the LCARdS Layout Card.
Lovelace resourcesLCARdS loads itself through the integration. An old manually added resource (e.g. /hacsfiles/lcards/lcards.js) or a duplicate loads it twice. Remove extras under Settings → Dashboards → ⋮ → Resources.
HA-LCARS themeShows whether an HA-LCARS theme is active. LCARdS works without it, but it is designed to pair with it.

Resource and extra_module_url checks need an admin user.

3. Common problems ​

  • Cards collapse or margins look wrong inside custom:layout-card: use LCARdS's own Layout Card instead. Change the type to custom:lcards-layout-card and remove layout_type; the rest of the config stays the same. See Sizing inside custom:layout-card.
  • Cards look out of date after an update: hard-refresh the page (Ctrl+Shift+R / Cmd+Shift+R) or clear the companion app's frontend cache.
  • Styling from card-mod stops working: card-mod no longer works with current Home Assistant; HA-LCARS uses UIX instead. Remove card-mod.
  • Moving over from CB-LCARS? See Coming from CB-LCARS for the equivalent of each card.

4. Report an issue ​

Still stuck? In the same section:

  • Report an issue opens a GitHub bug report with your LCARdS version, Home Assistant version and support info already filled in. It also copies the full info to your clipboard. Review the form, describe the problem, add your card YAML, then submit. Nothing is sent automatically.
  • Copy support info copies the same information, to paste into an existing issue or a Discussion.
  • Tick Include data-source names & entity IDs only if the problem involves data sources.

Expand Preview what will be shared to see exactly what is included. That means versions, browser, theme, UIX/card-mod status, integration options and the most recent LCARdS warnings. Those warnings can mention entity names, so review before sharing.

Please use the template

Issues need the bug report template so we have the versions and environment we need. Issues opened without it are labelled needs-template. Edit the issue to add the template sections, or use Report an issue.

Other ways to collect info ​

Download diagnostics, Home Assistant's standard diagnostics file: Settings → Devices & services → LCARdS → ⋮ → Download diagnostics. It contains the same backend facts plus Home Assistant's own system information.

Browser console (F12 → Console):

javascript
window.lcards.info()                    // quick summary
await window.lcards.support.copy()      // copy full support info to the clipboard
await window.lcards.support.openIssue() // copy + open a pre-filled bug report
await window.lcards.support.collect()   // raw support data (object)

Pass { includeConfig: true } to the support.* calls to include data-source names and entity IDs.
